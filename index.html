Firmware Troubleshooting

인캡 후 셧다운 오동작 — GPIO 인터럽트 경로 추적으로 PCB 재설계 없이 해결

① 증상
  • 삼킴장애 측정용 웨어러블을 몰딩(인캡)한 뒤 충격·시간 경과 시 동작 정지
  • BLE 탐색 불가
  • 무선충전 코일 위에 올리면 재동작
② 1차 가설 → 실패
  • 몰딩 중 납땜부 손상 의심
  • 디바이스 재제작 + 펌웨어 일부 수정
  • → 증상 동일
③ 단서 · 접근
  • "충전하면 다시 살아난다" → 고장이 아니라 저전력 진입 가능성
  • 슬립 진입 경로와 웨이크업 소스를 추적
④ 원인
  • 셧다운 신호용 P0.28 GPIO가 풀업 없이 falling-edge 인터럽트
  • ISR에서 Shipping_flag set → main loop에서 System OFF
  • 정상 종료 경로라 반환값 성공 · 로그 미기록 가능
⑤ 해결 · 검증
  • 내부 풀업 설정 + 일정 시간 유지 시에만 셧다운하는 디바운스
  • 누름·낙하 시험에서 재발 없음
  • 추가 제작 3대에서 동일 확인
Before
P0.28: input, no pull → falling edge IRQ → Shipping_flag = true main loop: Shipping_flag 확인 → System OFF 진입 (BLE 정지)
After
P0.28: internal pull-up 설정 신호가 일정 시간 유지될 때만 셧다운 (debounce) → 두 조치를 함께 적용해 오동작 재발 없음

Outcome

  • 펌웨어 수정만으로 문제를 해결해 PCB 재설계를 피함
  • 함수 반환값·로그만으로 보이지 않는 문제를 입력 신호 → 인터럽트 → 메인 루프 → 전원 상태까지 실행 흐름으로 추적
  • 증상을 세분화해 원인이 하드웨어·펌웨어 중 어디에 영향을 주는지 확인하는 디버깅 습관

AI-driven Semiconductor Process Optimization

Process Modeling, Inverse Prediction, and AI-based Optimization

Research Objective

  • UV dose와 Cr wet etching time에 따른 Fill Factor(FF)·Average Line Width(LW) 예측
  • 목표로부터 적합한 공정조건을 역으로 도출하는 AI-based inverse process design
  • 반복적인 trial-and-error를 줄이는 data-driven process optimization framework 구축

Dataset & Qualification

  • 15개 공정조건에서 총 225개 실험 데이터 확보
  • SEM image를 ImageJ로 분석하여 패턴 면적 및 총 길이 측정 후 FF·LW 정량화

My Contribution

  • 15개 공정조건의 225개 측정 데이터로 FF·LW를 예측하는 Python 분석 코드와 예측 구조 설계
  • 전체 island 면적을 먼저 예측하고 FF로 환산하는 구조 적용: 동일한 RBF 커널 릿지 회귀 조건에서 FF MAE 3.35 → 2.89 %p (약 14% 감소)

  • Target FF/LW 기반 inverse process search 알고리즘 구현
  • 신규 조건 시편 제작은 하드웨어 팀이 담당하고, 예측값–실측값 검증은 공동 수행
